# AWS S3 and compatible storage

Both destinations use the same standard-library HTTPS/SigV4 backend. There is no AWS
CLI or SDK dependency. Configure endpoint, signing region, existing bucket and a
unique installation prefix, such as `nextcloud/client-01`. Path-style bucket access
is used; the service must support it. For AWS use the correct regional endpoint
(e.g. `https://s3.eu-west-1.amazonaws.com`) and matching region. Redirects are refused
to prevent credential forwarding. TLS certificate validation remains enabled.

In settings provide an access key, secret key and optional session token. Blank
credential fields preserve the existing root-only file. New credentials are required
when changing the endpoint. Session credentials must be refreshed before expiry;
there is no IMDS, workload-identity or automatic STS refresh integration. Backend
errors report HTTP status and guidance without response bodies, signed headers or
credentials. Retries cover transient network failures, throttling and server errors.

The bucket must already exist. This project does not create buckets, change IAM,
disable Object Lock or modify bucket policy. Use a dedicated principal restricted to
this installation prefix and enable appropriate encryption at rest. `AES256` server-
side encryption may be selected; otherwise the bucket's default is used. KMS can be
provided through the bucket default and its required principal permissions.

## Required API permissions

On the bucket:

- `s3:ListBucket`, restricted to `PREFIX/generations/` and its descendants.
- `s3:GetBucketVersioning`.
- `s3:ListBucketVersions`, with the same prefix restriction if versioning is enabled
  or suspended.

On `BUCKET/PREFIX/generations/*`:

- `s3:PutObject`, `s3:GetObject`, `s3:DeleteObject`.
- `s3:DeleteObjectVersion` for versioned/suspended buckets.

No `ListAllMyBuckets`, bucket creation, public access or cross-prefix permission is
required. Configure IAM for the actual bucket/prefix rather than copying a broad
wildcard policy. The client needs delete permission for retention and connection
probe cleanup; insufficient permission is reported as failure.

## Recovery-point behavior

Archives are chunked into objects no larger than 64 MiB, avoiding multipart APIs
and single-object limits for large data sets. Uploads are sequential and require a
local snapshot; this favors a small, testable implementation over maximum throughput.
The manifest is uploaded last. Inventory lists only committed manifests; downloads
verify every size/hash before restore. The local operation lock serializes backups,
restores and retention on this installation. Do not share a prefix between independent
writers.

Retention and deletion query bucket versioning. Enabled/suspended versioning causes
all versions and delete markers for the selected generation to be removed using
version IDs. Unversioned deletion removes the current objects. Paginated listing
is supported in both cases. Keys outside the validated generation namespace are
never selected, even if an endpoint returns them in a listing.

Object Lock, legal holds or denied version deletion produce an explicit failure;
the client never bypasses them or reports a completed purge. Configure retention
policies to be compatible with your immutability requirements, or let the provider
manage immutable lifecycle expiry. Committed-artifact usage excludes older object
versions, partial uploads and service-side billing overhead; inspect bucket metrics
for billed usage.

Disaster recovery uses the same bucket/prefix with freshly supplied valid credentials.
It does not require the SSH provider API. Do not change the prefix to a new identity
when attempting to recover an existing installation.
